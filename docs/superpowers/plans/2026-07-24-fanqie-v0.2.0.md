# NovelScope API V0.2.0 番茄接入实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留起点现有行为和历史数据的前提下，为统一榜单与书籍详情 API 接入番茄小说，并支持 74 个静态榜单、详情缓存、双平台定时刷新和安全失败语义。

**Architecture:** 先把现有起点实现迁移到“平台榜单目录 + 站点独立模块”的通用契约，再增加番茄目录、Playwright 浏览器客户端和纯解析器。业务 Service 仍负责目录校验、完整性、TTL、stale 回退与 HTTP 错误边界，Repository 仍是 Prisma 的唯一业务访问边界。

**Tech Stack:** NestJS 11、TypeScript 5.7、Prisma 6、PostgreSQL、Playwright 1.61、Cheerio 1.2、Jest 30、Supertest

- 本计划按项目要求采用“功能优先、测试后补”：Task 1-10 先完成生产代码、数据库迁移、文档和受控功能冒烟；Task 11-14 再集中补写与调整测试；Task 15 做全量验收。

## 记录点使用规则

每个 Task 都带有一个“记录点”，它是该任务跨会话恢复时的权威状态，作用类似游戏存档点。执行者恢复工作时必须先读取最近一个任务的记录点，再从“恢复入口”继续，不凭记忆猜测进度。

- `状态` 只允许使用 `未开始`、`进行中`、`阻塞`、`已完成`。
- 开始任务时立即把状态改为 `进行中`，写入 Asia/Shanghai 时区的 ISO 8601 `最近更新` 时间，并把“恢复入口”指向正在执行的 Step。
- 每完成一个 Step，立即勾选对应复选框、递增“已完成步骤”，把“恢复入口”改为下一 Step，并记录刚刚运行的命令及实际结果。不要等多个 Step 完成后批量更新。
- 验证命令运行后，必须在“验证证据”中记录命令、退出码和关键计数；不得只写“通过”。失败时记录实际错误摘要，不得把失败步骤标记完成。
- 创建提交后立即记录短 commit SHA 和提交标题。提交失败或暂未提交时如实保留当前状态。
- 遇到阻塞时立即把状态改为 `阻塞`，在“阻塞/备注”中写清已经尝试的操作、原始错误摘要和继续所需条件。
- 离开会话、切换任务或触发上下文压缩前，必须更新当前记录点。只有全部复选框完成、验证证据齐全且提交已记录时，才能把任务状态改为 `已完成`。
- 记录点只保存执行状态和可复现证据，不写 Cookie、token、数据库 URL、上游 HTML或其他敏感信息。
