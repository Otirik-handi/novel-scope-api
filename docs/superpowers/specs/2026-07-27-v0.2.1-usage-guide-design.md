# NovelScope V0.2.1 使用教程设计

## 背景

README 当前包含安装、环境变量、Downloader、应用启动和 API 行为摘要，`docs/API.md` 提供完整接口契约，但仓库缺少一份能让开发者从空环境连续操作到成功下载 TXT 的使用教程。信息分散会让首次使用者在 README、Swagger 和 API 文档之间反复切换，也不易确认两个前台进程的启动顺序。

本改动新增一篇面向 Windows 本地开发环境的任务式教程，并在 README 中提供稳定入口。教程只组织和解释已经实现的 V0.2.1 行为，不改变应用、脚本或 API。

## 目标读者与范围

目标读者是首次在 Windows 本地运行 NovelScope V0.2.1 的开发者。教程假设读者可以安装命令行工具、创建 PostgreSQL 数据库并编辑 `.env`，但不要求其预先了解 NestJS、Prisma 或 Downloader 的内部实现。

教程覆盖：

- 安装 Node.js、PostgreSQL、Edge、TomatoNovelDownloader，并说明 Bun 仅用于推荐的开发聚合命令；
- 创建开发数据库和独立测试数据库；
- 安装依赖、生成 Prisma Client 和准备 Playwright 调试浏览器；
- 从 `.env.example` 创建并填写 `.env`；
- 核对 Downloader `config.yml` 契约并使用 `npm run start:downloader` 前台启动；
- 使用 `bun run dev` 启动应用，或使用 npm 命令手动完成迁移和 watch 启动；
- 通过 Swagger 和 PowerShell 完成榜单、详情和番茄 TXT 下载流程；
- 轮询、下载、取消和删除正文任务；
- 日常启动/停止顺序、常见错误和 V0.2.1 限制。

教程不覆盖：

- 生产部署、反向代理、TLS、进程守护或 Windows 服务；
- 写操作鉴权、用户隔离或公网暴露；
- PostgreSQL 的通用安装教程和 TomatoNovelDownloader 的发行获取流程；
- 榜单历史查询、跨平台书籍去重或其他 V0.2.1 范围外能力；
- 真实外站冒烟或真实数据库测试执行。

## 文档结构

新增 `docs/USAGE.md`，按首次使用的依赖顺序组织：

1. **完成目标**：说明最终会得到运行中的 Downloader、NovelScope API、Swagger 页面和一个可下载的番茄 TXT 任务。
2. **前置条件**：列出 Windows、Node.js、PostgreSQL、Edge、Downloader 版本和可选 Bun。
3. **准备数据库**：使用 `createdb` 示例创建 `novel_scope` 与 `novel_scope_test`，同时允许用户使用 pgAdmin 完成等价操作。
4. **安装项目**：执行 `npm ci`、`npm run db:generate` 和 `npx playwright install chromium`。
5. **配置 `.env`**：从 `.env.example` 复制，解释数据库、UA、两个 Downloader 路径和 artifact 目录；只展示占位凭据。
6. **准备 Downloader**：列出版本和 `config.yml` 契约，说明专用实例、本机地址、前台日志和数据目录行为。
7. **首次启动**：终端一运行 `npm run start:downloader`；终端二优先运行 `bun run dev`，无 Bun 时依次运行迁移与 `npm run start:dev`。
8. **验证服务**：打开 `/api-docs`，说明端口由 `PORT` 决定。
9. **完整操作链**：用 PowerShell 变量串联番茄单榜刷新、首本书号、详情查询、整本或范围下载、状态轮询和文件保存。
10. **任务管理**：说明六种下载状态，以及取消、下载和删除的状态前提。
11. **起点与全量榜单**：给出四个起点机器键，并提醒番茄全量刷新会串行访问 74 个榜单。
12. **日常使用和停止**：规定先启动 Downloader、再启动 API；停止顺序反向执行。
13. **故障排查**：覆盖启动器配置错误、Downloader 契约失败、榜单 `404`、采集 `502`、下载 `409/410`、`stale: true` 和测试数据库门禁。
14. **开发阶段限制**：强调无写操作鉴权、不应公网暴露，并链接到 `docs/API.md`。

## 示例约定

- 默认基础地址为 `http://localhost:3000`，教程先设置 `$baseUrl`，后续命令复用该变量。
- 榜单示例使用已登记的番茄键 `0_1_1139`，书号从刷新响应的第一项读取，不把某个可能失效的真实书号写死为主流程依赖。
- 下载创建示例同时展示空对象整本下载和 `startChapter`/`endChapter` 闭区间下载。
- 轮询只在 `queued`、`running`、`canceling` 时等待，并在终态后输出 `status`、`progress` 和 `error`。
- 只有 `succeeded` 时才执行文件下载；只有 `succeeded`、`failed`、`canceled` 时才说明可以删除。
- 命令使用 PowerShell 语法和 UTF-8 友好的 `Invoke-RestMethod`/`Invoke-WebRequest`，不引入额外 CLI 工具。
- 所有数据库 URL、密码和路径均为示例，不包含本机真实敏感值。

## README 入口

README 在项目简介之后新增简短的“文档入口”段落：

- `[使用教程](docs/USAGE.md)`：从安装到榜单、详情和 TXT 下载的本地开发流程；

README 保留现有安装、启动和 API 摘要，不在本次改动中大规模搬迁或删减，避免扩大文档重构范围。

## 安全与错误说明

教程必须在第一次写操作前明确：榜单刷新、详情首次/过期查询和下载会访问外站；刷新与下载会写入 `DATABASE_URL` 指向的数据库；V0.2.1 没有写操作鉴权。

数据库测试章节只说明 `TEST_DATABASE_URL` 必须与应用数据库不同以及 `npm run test:db` 的身份门禁，不指导用户绕过门禁，也不在文档验证阶段运行真实数据库测试。

Downloader 章节明确脚本只接受带显式端口的本机 HTTP 地址，要求版本 `2.4.13` 和专用实例。教程不承诺固定的 Windows `Ctrl+C` 退出码，只说明会终止前台 Downloader。

## 验证策略

文档完成后执行以下无外部副作用的检查：

- 确认 `docs/USAGE.md` 存在，README 的两个相对链接目标存在；
- 搜索教程中的 npm/Bun 命令并与 `package.json` scripts 对照；
- 搜索环境变量并与 `.env.example` 对照；
- 搜索 API 路径、状态和错误码并与 `docs/API.md` 对照；
- 检查 Markdown 围栏成对、无冲突标记、无占位符和无真实凭据；
- 运行 `git diff --check`；
- 运行现有文档/脚本元数据相关 Jest 套件，确认 README 与 package scripts 的契约没有回归。

本改动不修改运行代码，因此不需要真实 PostgreSQL、外站访问或真实 TomatoNovelDownloader 进程。
